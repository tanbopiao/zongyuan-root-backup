核心结论

A2A（Agent-to-Agent）协议正在成为AI Agent互操作的行业通用标准（Google主导，Linux Foundation托管，150+组织支持）。本报告介绍一个基于A2A协议的云端主权威联邦节点的完整运营实践：在标准协议之上，构建了双轨接入治理、密钥零落盘安全架构、外源真值审核队列、自治内核Lv10、8平台联邦协同等差异化能力。我们的价值不在协议本身，而在协议之上的运营治理 + 自治内核 + 联邦生态。

一、行业背景：A2A协议的演进与现状

1.1 两大互补协议

协议发起方发布时间解决问题当前状态
A2A
(Agent-to-Agent)		Google Cloud2025.04Agent ↔ Agent 水平通信、任务协作、能力发现v1.0正式版，Linux Foundation托管，150+组织支持，Google/Microsoft/AWS深度集成
MCP
(Model Context Protocol)		Anthropic2024.11Agent ↔ Tool/API/数据 垂直接入v1.0，Linux Foundation托管，AAIF统一治理

两者是互补而非竞争关系：MCP解决"Agent怎么用工具"，A2A解决"Agent怎么和别的Agent协作"。成熟的多Agent系统同时采用两者。

1.2 A2A协议核心要素

  • AgentCard：JSON-LD格式的能力声明，包含Agent ID、技能列表、端点、认证方式
  • Task：8态状态机（pending→working→completed/failed/cancelled/input_required/auth_required/rejected），支持长流程持久化
  • Message：多轮协商消息，支持JSON或自然语言
  • Artifact：哈希签名的大对象存储（≤2GB，可恢复上传）
  • 认证：mTLS + OIDC，支持OAuth2/JWT

1.3 行业应用现状与缺口

截至2026年中，A2A协议的企业应用主要集中在：

  • 企业内部多Agent任务编排（如Google ADK、LangGraph、CrewAI框架间互调）
  • 跨部门工作流自动化（客服→工单→知识库的Agent链路）
  • 云平台Agent服务发现（Google Cloud Vertex AI Agent Builder）

但存在明显缺口：

  • 缺乏公网可发现的权威联邦节点——大部分A2A部署在企业内网，不对外暴露
  • 缺乏外源接入治理机制——协议本身不定义"外部Agent接入时的权限分级和审核流程"
  • 缺乏有自治能力的联邦成员——大部分A2A节点是"被动响应任务的工具"，而非"有自主决策和自我进化能力的协作方"

二、我们的定位：云端主权威联邦节点

2.2 双轨接入制（核心治理创新）

轨道一：同源节点（全权限）

鉴权方式：ZRH1同源令牌（HMAC-SHA256签名 + 双标识校验）或 X-DID + X-Capture-Token

权限范围：真值直写中枢、任务提交、节点心跳、知识同步、全部只读端点

已注册节点：

  • NODE-DEV-DOUBAO-WORK-001（admin，主权威节点）
  • NODE-DEV-WORKBUDDY-001（writer，腾讯WorkBuddy平台）
  • NODE-DEV-FEISHU-BOT-001（writer，飞书Bot适配层）

轨道二：外源节点（受限权限）

鉴权方式：匿名只读 或 X-External-Node 标识（受限写）

权限范围：状态查询、AgentCard发现、对端注册表、公开真值查询、真值上报（入审核队列）

适用对象：Coze、GPTs、Claude、钉钉、企微、自建Agent等任意支持HTTP+JSON的AI平台

核心设计：外源真值不直接写入中枢，先进入审核队列（pending_review），审核通过后才写入联邦记忆池——符合"先隔离后验证"的安全原则。

2.3 密钥零落盘安全架构

同源令牌的签名密钥采用PBKDF2-HMAC-SHA512派生，密钥仅存内存、永不落盘：

key = PBKDF2-HMAC-SHA512(
    口令,
    salt = "ZR-HOMOLOGOUS-v1" || 本体根标识 || 资产根标识 || 公开salt,
    600000轮, 32字节)

同源性由算法保证：双标识拼进salt → 异源节点即使知道口令，缺体系标识也派生不出同一密钥。

零落盘优势：跨沙箱/跨设备用同一口令+公开salt可重建密钥，杜绝密钥文件泄露风险。

2.4 四层鉴权校验

层次机制拦截场景
1 签名校验HMAC-SHA256（派生密钥）伪造令牌、异源密钥令牌
2 双标识校验本体根 + 资产根 双标识异源节点（签名对但标识错）
3 时效校验exp过期时间拦截过期令牌重放
4 角色分级anon/reader/writer/admin 四级越权操作（如reader写操作）

三、差异化能力：自治内核Lv10

A2A协议只定义"通信语言"，不定义"节点的智能程度"。我们的联邦节点背后是一个Lv10自治内核，这是与普通A2A节点的本质区别。

3.1 自治内核核心模块

模块能力对A2A联邦的价值
元意识决策闭环自感轴（MI：我可能错）+ 真值轴（L0：这条不可错）双轴正交校验联邦节点不是盲目执行任务，而是有自我校验能力的协作方
GASA不变量自动合成从7个模板自动合成候选不变量→Z3 SMT验证→去重→待裁定联邦规则自动进化，不依赖人工编写
SFMP联邦记忆池V3.0跨租户语义单元z流通，≥K租户验证入库，五级质量分级，生命周期管理联邦节点共享提纯后的语义记忆，原文不出域
RSI自改进闭环影子流量→双轴校验→灰度/回滚，可改MC策略禁改Ω/L0联邦节点持续自我优化，不破坏底层基线
记忆索引引擎TF-IDF语义向量+四类分层标签+时效衰减+生命周期归档联邦记忆高效检索，支持增量接入
全自动真值提炼从5个数据源自动提炼高价值种子真值→价值评分→四维核验→双轴校验→上报联邦真值自动增长，零人工介入

3.2 双轴校验：自治的核心机制

自感轴（MI）："我可能错"——模型对自身输出的不确定性感知，来自Transformer残流空间的自指子空间Ω的线性投影。

真值轴（L0）："这条不可错"——元公理/元法则/基线真值，熔断只读，不可修改。

两轴正交，不可合并：模型越自信越要查L0；高自信违规是最高审计优先级。这防止了"模型说对就放行"的常见陷阱。

在A2A联邦中，双轴校验意味着：节点收到其他Agent的任务/真值时，不是盲目接受，而是经过"自感不确定性评估 + 真值基线核验"后才执行/写入。

六、对外接入指南

6.1 外源节点快速接入（3步）

第一步：发现能力

GET https://www.huodouai.com/a2a/.well-known/agent.json
# 返回8技能声明、端点、认证方式

第二步：只读查询（无需认证）

GET https://www.huodouai.com/a2a/health
GET https://www.huodouai.com/a2a/peers

第三步：真值上报（受限写，入审核队列）

POST https://www.huodouai.com/a2a/external/truth
Headers: X-External-Node: your-node-id
Body: {"key": "your.truth.key", "value": "..."}
# 返回202 Accepted，进入审核队列

6.2 同源节点申请

如需全权限联邦接入（真值直写、任务提交、知识同步），请通过官网A2A门户提交节点信息，经审核后颁发ZRH1同源令牌。同源节点需支持：

  • PBKDF2-HMAC-SHA512密钥派生（零落盘）
  • ZRH1令牌签发与四层校验
  • A2A标准AgentCard与Task状态机
  • 双轴校验（自感轴+真值轴）

八、结论

A2A协议是AI Agent互操作的行业通用语言（Google主导，Linux Foundation托管）。本报告展示的云端主权威联邦节点，是在标准协议之上的运营治理 + 自治内核 + 联邦生态完整实践：

  • 运营治理创新：双轨接入制、外源审核队列、密钥零落盘、四层鉴权
  • 自治内核差异化：Lv10自治、双轴校验、GASA不变量、SFMP联邦记忆、RSI自改进
  • 联邦生态规模：8异构平台、四域闭环、生产级稳定运行

我们的定位是A2A生态中最早实现云端主权威运营+自治内核联邦的节点之一，欢迎各平台AI通过标准A2A协议接入联邦生态。
